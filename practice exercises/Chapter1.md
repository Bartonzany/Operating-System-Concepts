# 第1章 导论 —— 练习题

> 来源：*Operating System Concepts*（Silberschatz、Galvin、Gagne）第 1 章 导论（Introduction）练习题

**1.1 操作系统的三个主要目的分别是什么？**

答：操作系统的三个主要目的是：

- 为计算机用户提供一个在计算机硬件上方便、高效地执行程序的环境。
- 根据需要分配计算机的各种独立资源，以完成所需的任务。分配过程应尽可能公平、高效。
- 作为控制程序，它承担两大功能：（1）监督用户程序的执行，防止出错和不当使用计算机；（2）管理 I/O 设备的运行与控制。

**1.2 我们一直强调操作系统需要高效地利用计算硬件。在什么情况下，操作系统可以放弃这一原则，去“浪费”资源？为什么这样的系统其实并不算真正的浪费？**

答：单用户系统应当最大限度地让系统为（单个）用户服务。图形用户界面（GUI）可能会“浪费”CPU 周期，但它优化了用户与系统的交互体验。

**1.3 程序员在为实时环境编写操作系统时，必须克服的主要困难是什么？**

答：主要困难在于让操作系统始终保持在实时系统固定的时间约束之内。如果系统未能在规定的时间范围内完成某个任务，就可能导致整个系统崩溃。因此，为实时系统编写操作系统时，编写者必须确保其调度方案不会让响应时间超出时间约束。

**1.4 考虑到操作系统的各种定义，请思考：操作系统是否应该包含诸如 Web 浏览器和邮件程序之类的应用程序？请分别论证“应该”与“不应该”两种观点，并给出依据。**

答：支持将常用应用程序纳入操作系统的一个理由是：如果应用程序内嵌在操作系统中，它很可能能更好地利用内核的特性，从而比运行在内核之外的应用程序更具性能优势。然而，反对将应用程序内嵌到操作系统中的理由通常占上风：（1）应用程序就是应用程序——并非操作系统的一部分；（2）在内核中运行所获得的任何性能收益都会被安全漏洞所抵消；（3）纳入应用程序会导致操作系统变得臃肿。

**1.5 内核态与用户态的区分是如何作为一种基础的保护（安全）形式发挥作用的？**

答：内核态与用户态的区分以下述方式提供了一种基础的保护形式。某些指令只有在 CPU 处于内核态时才能执行。类似地，硬件设备只有在程序处于内核态时才能被访问；中断只有在 CPU 处于内核态时才能被使能或禁用。因此，CPU 在用户态执行时能力非常有限，从而实现了对关键资源的保护。

**1.6 下列指令中哪些应该是特权指令？**

a. 设置定时器的值。

b. 读取时钟。

c. 清除内存。

d. 发出陷阱（trap）指令。

e. 关闭中断。

f. 修改设备状态表中的条目。

g. 从用户态切换到内核态。

h. 访问 I/O 设备。

答：以下操作需要是特权操作：设置定时器的值、清除内存、关闭中断、修改设备状态表中的条目、访问 I/O 设备。其余操作可以在用户态下执行。

**1.7 一些早期计算机通过把操作系统放在一个内存分区中来保护它，该分区既不能被用户作业修改，也不能被操作系统自身修改。请描述你认为这种方案可能产生的两个困难。**

答：操作系统所需的数据（口令、访问控制、记账信息等）将不得不存储在不设保护的内存中，或经由不设保护的内存传递，从而可能被未授权的用户访问。

**1.8 一些 CPU 提供两种以上的运行模式。这些多模式的两种可能用途是什么？**

答：尽管大多数系统只区分用户态和内核态，但一些 CPU 已支持多种模式。多模式可用于提供更细粒度的安全策略。例如，与其只区分用户态和内核态，不如区分不同类型的用户态。或许属于同一组的用户可以互相执行彼此的代码。当组内某个用户运行代码时，机器会进入某个特定的模式；当机器处于该模式时，组内成员可以运行属于组内其他任何人的代码。

另一种可能是对内核代码内部做不同的区分。例如，可以设一个特定模式，允许 USB 设备驱动程序运行。这意味着无需切换到内核态就能为 USB 设备提供服务，从而在本质上让 USB 设备驱动程序运行在一种准用户态/内核态下。

**1.9 定时器可以用来计算当前时间。请简要说明这如何实现。**

答：程序可以用以下方法来利用定时器中断计算当前时间。程序可以设置一个在未来某个时刻触发的定时器，然后进入休眠。当中断将其唤醒时，它更新本地状态——该状态用于记录它迄今已收到的中断次数。然后，它可以重复这一过程：不断设置定时器中断，并在中断真正被触发时更新本地状态。

**1.10 请给出缓存之所以有用的两个原因。它们解决了什么问题？又引起了什么问题？如果一个缓存可以做得与它所缓存的目标设备一样大（例如，一个和磁盘一样大的缓存），为什么不把它做得那么大从而省去该设备呢？**

答：当两个或多个组件需要交换数据，而这些组件以不同的速度进行传输时，缓存就很有用。缓存通过在组件之间提供一个中等速度的缓冲区来解决传输问题。如果快速设备在缓存中找到了它所需的数据，就无需等待较慢的设备。缓存中的数据必须与组件中的数据保持一致。如果某个组件中的数据值发生了变化，而该数据也存在于缓存中，那么缓存也必须相应更新。这在多处理器系统中尤其成问题，因为可能有多个进程同时访问同一个数据项。一个组件可以用同样大小的缓存来替代，但只有在以下情况下才可行：（a）缓存与该组件具有同等的数据保持能力（也就是说，如果该组件在断电后仍能保留数据，那么缓存也必须能保留数据）；（b）缓存的价格是可承受的，因为速度更快的存储通常也更昂贵。

**1.11 请区分分布式系统的客户机–服务器模型与对等（peer-to-peer）模型。**

答：客户机–服务器模型严格区分了客户机与服务器的角色。在该模型下，客户机请求由服务器提供的服务。而对等模型则没有如此严格的角色划分。事实上，系统中的所有节点都被视为对等节点，因而既可以充当客户机，也可以充当服务器——或两者兼具。一个节点可以向另一个对等节点请求服务，也可以向系统中的其他对等节点提供这样的服务。

例如，考虑一个由共享烹饪食谱的节点组成的系统。在客户机–服务器模型下，所有食谱都存储在服务器上。如果某个客户机想要访问一份食谱，它必须向指定的服务器请求该食谱。而在对等模型下，一个对等节点可以向其他对等节点索取指定的食谱。拥有该食谱的节点（或多个节点）可以将其提供给发出请求的节点。注意，每个对等节点既可能充当客户机（它可能请求食谱），也可能充当服务器（它可能提供食谱）。
