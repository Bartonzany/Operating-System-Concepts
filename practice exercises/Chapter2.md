# 第2章 操作系统结构 —— 练习题

> 来源：*Operating System Concepts*（Silberschatz、Galvin、Gagne）第 2 章 操作系统结构（Operating-System Structures）练习题

**2.1 系统调用的用途是什么？**

答：系统调用允许用户级进程向操作系统请求服务。

**2.2 命令解释器的用途是什么？为什么它通常独立于内核？**

答：它从用户或命令文件中读取命令并执行它们，通常是将这些命令转换为一个或多个系统调用。它通常不属于内核的一部分，因为命令解释器容易发生变化（经常需要修改）。

**2.3 在 UNIX 系统上，命令解释器或 shell 为了启动一个新进程，必须执行哪些系统调用？**

答：启动一个新进程需要执行一个 `fork()` 系统调用和一个 `exec()` 系统调用。`fork()` 调用会克隆当前正在执行的进程，而 `exec()` 调用则用一个基于不同可执行文件的新进程覆盖调用进程。

**2.4 系统程序的用途是什么？**

答：系统程序可以被视为有用的系统调用的集合（捆绑）。它们向用户提供基本功能，这样用户就无需为常见问题自行编写程序。

**2.5 分层法系统设计的主要优点是什么？分层法的缺点又是什么？**

答：与所有模块化设计的情况一样，以模块化的方式设计操作系统有若干优点。系统更容易调试和修改，因为改动只影响系统中有限的部分，而不会触及所有部分。信息只保存在需要的地方，并且只能在一个确定且受限的区域内被访问，因此任何影响该数据的错误（bug）必然被限制在某个特定的模块或层中。分层法的主要缺点是性能较差，这是由于为了获得操作系统提供的某项服务，必须穿越不同层次而产生的开销所致。

**2.6 列出操作系统提供的五种服务，并说明每一种服务如何为用户带来便利。在哪些情况下，用户级程序不可能提供这些服务？请解释你的答案。**

答：这五种服务是：

a. **程序执行**。操作系统把文件的内容（或若干段）加载到内存中并开始执行它。用户级程序无法被信任去恰当地分配 CPU 时间。

b. **I/O 操作**。必须在非常低的层次上与磁盘、磁带及其他设备进行通信。用户只需指定设备以及要在其上执行的操作，系统会将该请求转换为设备或控制器专用的命令。用户级程序不能被信任只访问它们有权访问的设备，并且只在设备空闲时才去访问它们。

c. **文件系统操作**。在文件的创建、删除、分配和命名中有许多细节是用户不应去处理的。磁盘空间块被文件占用，必须加以跟踪。删除文件需要移除文件名字信息并释放已分配的块。还必须检查保护措施以确保文件访问是恰当的。用户程序既无法确保遵守保护方法，也不能被信任在分配时只分配空闲块、并在删除文件时释放块。

d. **通信**。系统之间的消息传递要求把消息转换为信息包，发送到网络控制器，跨越通信介质传输，并由目标系统重新组装。还必须进行包的排序和数据纠错。同样，用户程序可能无法协调对网络设备的访问，或者可能接收到发往其他进程的包。

e. **错误检测**。错误检测发生在硬件和软件两个层面。在硬件层面，必须检查所有的数据传输，以确保数据在传输过程中没有被损坏。介质上的所有数据都必须被检查，以确认它们自写入介质以来没有发生变化。在软件层面，必须检查介质的数据一致性——例如，已分配和未分配的存储块数量是否与设备上的总块数相符。在这些情况下，错误通常是独立于进程的（例如磁盘上数据的损坏），因此必须有一个全局程序（即操作系统）来处理所有类型的错误。此外，当错误由操作系统处理时，进程就无需包含用于捕获和纠正系统上所有可能错误的代码。

**2.7 为什么有些系统把操作系统存储在固件（firmware）中，而另一些系统把它存储在磁盘上？**

答：对于某些设备（例如嵌入式系统），可能没有带文件系统的磁盘可用。在这种情况下，操作系统就必须存储在固件中。

**2.8 如何设计一个系统，使其在启动时可以在多个操作系统之间进行选择？引导程序需要做什么？**

答：考虑一个既想运行 Windows，又想运行三个不同 Linux 发行版（例如 RedHat、Debian 和 Ubuntu）的系统。每个操作系统都会存储在磁盘上。在系统启动过程中，一个特殊的程序（我们称之为引导管理器，boot manager）会决定启动到哪个操作系统。这意味着，引导管理器会在系统启动期间首先运行，而不是一开始就直接启动到某个操作系统。正是这个引导管理器负责决定要启动到哪个系统。通常，引导管理器必须存储在硬盘上的特定位置，才能在系统启动期间被识别。引导管理器通常会向用户提供可启动系统的选择列表；如果用户没有做出选择，引导管理器通常也被设计为启动到一个默认的操作系统。
